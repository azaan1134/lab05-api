## 4. Postman collection (Даалгавар 1, 3)

- Файл: `lab05-collection.json` (Postman Collection v2.1, Postman-аас export хийсэн).
- `{{baseUrl}}` = `http://localhost:3000` (collection variable).
- Тест бүр тусдаа хавтастай (T1–T11) бөгөөд өөрийн setup `PUT /students/...`, `PUT /courses/...` хүсэлтийг өөрөө хийнэ. Ингэснээр тестүүд хоорондоо хамааралгүй, дараалал солигдсон ч ажиллана.
- Oracle бүр хоёр `pm.test`-ээс бүрдэнэ: **статус код** болон **`result` утга**. T5, T6 дээр нэмэлтээр `missing` массивыг шалгана.
- `registrationID`-ийн яг утгыг шалгаагүй, зөвхөн хариу `OK` эсэхийг шалгана (T1 дээр registrationID нь тоо байх нөхцөлийг хүснэгтэд тэмдэглэсэн).
- Нийт **11 тест, 25 request (14 setup PUT + 11 POST), 24 assertion**.

## 5. Newman-аар автоматжуулсан үр дүн (Даалгавар 4)

Newman-ыг Windows PowerShell дээр `cmd`-ээр дамжуулан ажиллуулсан (Монгол үсэг мурзихгүйн тулд), exit code-ыг файл бүрийн төгсгөлд `exit=` мөрөөр нэмж хадгалсан:

```powershell
cmd /c "newman run lab05-collection.json --color off --disable-unicode > results\newman-pass.txt 2>&1"
Add-Content -Path results\newman-pass.txt -Value "exit=$LASTEXITCODE" -Encoding utf8
```

| Ажиллуулалт | Файл | Collection | assertions executed | assertions failed | Exit code |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **PASS** | `results/newman-pass.txt` | `lab05-collection.json` | **24** | **0** | **0** |
| **FAIL** | `results/newman-fail.txt` | `lab05-collection-fail.json` | 24 | **1** | **1** |
| **DOWN** | `results/newman-down.txt` | `lab05-collection.json` (сервер унтраасан) | 24 | 24 | **1** |

Тестийн тоо (**24 assertion**) нь `results/newman-pass.txt`-ийн `assertions executed` тоотой тэнцүү.

- **PASS:** Бүх 11 тест, 24 assertion амжилттай, exit code **0**.
- **FAIL:** T1 дээрх статус oracle-ыг зориуд `201`-ийн оронд `200` гэж хүлээлгэсэн тусдаа `lab05-collection-fail.json`-оор ажиллуулахад `expected response to have status code 200 but got 201` алдаа гарч, 1 assertion унаж exit code **1** болсон. Энэ нь CI quality gate-ийн зарчим: нэг oracle унахад Newman тэгээс өөр exit code буцааж, pipeline-ыг зогсооно. 
- **DOWN:** Серверийг унтраасан (`Ctrl+C`) үед бүх 25 request `connect ECONNREFUSED 127.0.0.1:3000` алдаагаар унаж, exit code **1** болсон. `ECONNREFUSED` нь серверт холбогдож чадаагүй. DOWN үед 24 assertion-ын бүгд унасан нь хариу байхгүй тул `pm.response.json()` нь `undefined` болсонтой холбоотой, серверийн логик буруу гэсэн үг биш.

## 7. Дүгнэлт

Дизайны 5 алхмаас хамгийн хэцүү нь 2 ба 3-р алхам буюу сонголтууд болон төлөөлөх утгуудыг зөв тодорхойлох байлаа, учир нь эквивалент анги буруу гарвал үлдсэн тестүүд бүгд буруу чиглэлд явна. 36 хослолоос боломжгүй хослол таарсан: байхгүй оюутанд "урьдач хангах эсэх", байхгүй хичээлд "урьдач нөхцөл" гэсэн сонголт утгагүй тул тэдгээрийг хасаж, тестийн багцыг 11 болгон багасгасан. Хамгийн сонирхолтой нь давхар алдааны тохиолдол (T7, T8) байв: зааварт аль алдаа түрүүлж буцахыг заагаагүй тул тестээр тогтоосон бөгөөд сервер оюутны шалгалтыг (`ERROR_NO_STUDENT`, `ERROR_INACTIVE_STUDENT`) хичээл болон урьдач нөхцлийн шалгалтаас түрүүлж хийдэг. Хязгаарын тохиолдлууд (урьдачгүй хичээл, талбар дутуу, буруу JSON) нь happy path-аас өөр кодыг шалгаж өгсөн. Тест бүрийг өөрийн setup-тай, өвөрмөц хавтастай болгосноор тестүүд хоорондоо хамааралгүй болж, нэг нь унасан ч бусдад нөлөөлөхгүй болсон. Үр дүнд нь миний тестүүд сервер дээр ямар нэг согог илрүүлээгүй: бүх 24 assertion амжилттай болсон. Харин FAIL ажиллуулалтаар нэг oracle буруу байхад Newman exit code 1 буцааж, тест үнэхээр шалгалт хийж байгааг харуулсан. Postman-аар гараар тест бичих нь эхэндээ удаан боловч Newman-аар командын мөрөөс автоматаар ажиллуулах нь CI/CD-д шууд ашиглагдах боломжийг харуулсан.
